> **TL;DR**
>
> MIA（Memory Intelligence Agent）提出 Manager-Planner-Executor 三重架构，配合非参数记忆（沉淀经验）与参数记忆（吸收能力）的双向进化环路，让 Agent 在深度研究任务中从「失忆式工作」进化到「持续积累」。GPT-5.4 在 LiveVQA 和 HotpotQA 上分别提升 9% 和 6%，轻量级 Qwen2.5-VL-7B 获得平均 31% 的性能提升。
>
> **核心观点：Agent 的能力瓶颈不在模型本身，而在记忆的有效管理。小模型 + 好记忆架构，可以逼近大模型的表现。**

---

## 1. 背景：Agent 失忆式工作的困境

当前 Agent 在深度研究任务中面临一个根本性问题：**每次任务都从零开始**。

你让 Agent 做一个研究任务 A，它做完了。下一个任务 B 和 A 高度相关，但 Agent 不记得 A 里做过什么、发现过什么、什么方法有效。它重新开始，重复劳动。

这不是模型能力问题，是**记忆系统设计问题**。

---

## 2. MIA 的三重架构

MIA 采用了 Manager-Planner-Executor 三层分工：

```
┌──────────────────────────────────────────────────┐
│                  MIA 三重架构                     │
│                                                  │
│  Manager（记忆管理员）                            │
│  ─── 非参数化记忆系统                            │
│  ─── 整理和压缩历史搜索轨迹                      │
│                                                  │
│  Planner（规划师）                                │
│  ─── 参数化记忆智能体                            │
│  ─── 根据过往经验制定行动计划                    │
│                                                  │
│  Executor（执行者）                               │
│  ─── 在搜索计划指导下进行信息搜索与分析          │
│                                                  │
└──────────────────────────────────────────────────┘
```

### Manager：非参数记忆的管理员

非参数记忆是「写进去、读出来」的结构化存储，不参与模型参数更新。

Manager 的职责是把历史搜索轨迹整理、压缩、归纳，形成可供 Planner 使用的记忆摘要。

### Planner：参数化记忆的智能体

Planner 是真正「学习」的组件。它从历史经验中吸收教训，更新自己的参数，从而在面对新任务时能更好地规划。

关键设计：**Planner 在推理过程中实时进行参数更新和自我完善**——这就是 Test-time Learning（测试时学习）。

### Executor：执行者的职责

Executor 在 Planner 制定的计划指导下进行实际的信息搜索和分析。Executor 本身不学习，它的价值在于忠实地执行 Planner 的指令。

---

## 3. 双重记忆的双向进化环路

MIA 最核心的设计洞察是**非参数记忆与参数记忆的双向转化**：

```
非参数记忆 ←──→ 参数记忆
（沉淀经验）    （吸收能力）

Manager 写   →  Planner 读 → Planner 学习 → 更新参数
 Planner 执行 →  新经验  →  Manager 整理  →  非参数记忆更新
```

具体来说：

**非参数 → 参数**：Manager 把整理好的历史经验输给 Planner，Planner 据此调整自己的规划策略

**参数 → 非参数**：Planner 在执行中产生的新洞察，由 Manager 沉淀回非参数记忆

这是一个持续进化的闭环：每次任务结束后，两种记忆都得到更新，下次任务站在更高的起点上。

---

## 4. 交替强化学习：对齐规划与执行

Planner「会规划」和 Executor「会执行」是两种不同的能力。MIA 用**交替强化学习**让两者协同进化：

- 当 Executor 没能正确执行 Planner 的计划时，Planner 需要学会制定更可执行的计划
- 当 Planner 制定的计划执行效果差时，Executor 需要学会更好地理解 Planner 的意图

交替更新的结果是：**「想得到」和「做得到」逐渐对齐**。

---

## 5. 性能亮点

- **GPT-5.4** 在 LiveVQA 和 HotpotQA 任务上分别提升 **9% 和 6%**
- **Qwen2.5-VL-7B**（轻量级模型）在综合评测中获得平均 **31%** 的性能提升

31% 这个数字最有意思：它证明的不是「模型越大越好」，而是**「记忆架构的设计比模型大小更关键」**。

一个 7B 的模型如果有好的记忆系统，可以超越没有记忆系统的大模型。

---

## 6. 为什么重要

MIA 揭示了一个被忽视的关键问题：

> Agent 的能力瓶颈不在模型本身，而在记忆的有效管理。

这和人类智能的规律是一致的：专家之所以是专家，不是因为他脑子快，而是因为他有大量领域经验可以调用。

MIA 的双重记忆环路，第一次在系统层面实现了这个能力。
