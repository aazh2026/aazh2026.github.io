## 递归自我改进：一个需要实证的问题

"递归自我改进"（Recursive Self-Improvement, RSI）是通往 AGI 的热门叙事：AI 改进"训练 AI 的方法本身"，形成自我加速的飞轮。

但关键问题是：**今天的 LLM Agent 是否已经具备这个能力？**

注意，这不是"调超参数"，而是真正改变训练算法本身——损失函数、更新规则、训练流程。

## AI4AI-Bench 的严格评测设计

论文选取 **10 个真实 AI 研究仓库**，覆盖 10 类不同训练算法族（扩散模型训练、强化学习、权重平均、网络剪枝等）。

### 第一阶段：4 小时自由探索

- Agent 获得一张 B300 GPU
- 可自由读代码、改代码、跑训练、查看 proxy metric
- 时间到后，只保留源码，探索阶段的权重和缓存全部作废

### 第二阶段：最长 12 小时独立重跑

- 提交的源码在全新环境中从头执行
- 产出的模型交给**预先冻结、Agent 从未接触过的 evaluator** 打分
- 要击败的 baseline 是原始仓库自己的代码

这个评测设计的严格之处在于：**Agent 无法通过接触 evaluator 来作弊，必须靠真正的算法理解来提升性能。**

## 清醒的结果

**最强 Agent 的改进得分仅为 0.16（满分 1.0）。**

所有 Agent 在所有任务上，都没能实质性地超越仓库原始代码的表现。

这意味着：当前的 LLM 编码 Agent 在"设计更好的 AI 算法"这件事上，距离真正的递归自我改进还有很大差距。Agent 擅长的是在既定算法框架内调优（改超参数、增加训练步数），但当需要理解训练动态、定位机制问题、提出新算法思路时，能力严重不足。

## 为什么这篇论文引发轰动

在 X 上发布 7 小时内获得 **110 万次浏览**，近 **3000 条讨论**，登上 X 的 Today News。

原因：它给出了 RSI 讨论中缺失的**实证基线**。与其争论"AI 自我改进会不会失控"，不如先测一测它到底能做到什么程度。

结论清醒：**人类算法研究员的核心能力——从训练动态中诊断问题、修改机制而非参数——仍然是 Agent 难以逾越的壁垒。**

## 对"AI 自我改进"讨论的降温

AI4AI-Bench 的价值不是否定 RSI 的方向，而是建立了**当前能力的真实基线**：

| 能力 | 当前 Agent 水平 |
|------|----------------|
| 调超参数 | 可做到，有改善 |
| 增加训练步数 | 可做到，有改善 |
| 改进损失函数 | 做不到 |
| 理解训练动态 | 做不到 |
| 提出新算法思路 | 做不到 |

这个分层对投资和研究方向有直接影响：在 Agent 真正能"修改机制"之前，"AI 设计更好的 AI"还是人的工作。
