## 从"补全"到"意图推理"的跨越

传统的代码 LLM 预训练范式是：**给定前 N 个 token，预测第 N+1 个**。不管输入是文件级别还是仓库级别，本质上都是在做"**文本接龙**"——模型学到的是"代码通常长什么样"，而不是"这段代码为什么要这样写"。

这种模式的局限在实践中暴露得很清楚：

- PR 摘要生成：模型只能描述 diff 本身，说不清动机
- 回归风险分析：模型不会推理"改这里会破坏那里的逻辑依赖"
- 重构影响面分析：模型能补全代码，但不知道重构传播范围

原因是：**diff 本身包含了意图信息，但以文件/仓库为单位的预训练方式把 diff 拆散成了无结构的 token 流**。

## Diff + Review Intent 预训练的核心思想

这篇论文的预训练目标是：**让模型同时建模变更的内容（diff）和变更的理由（review intent）**。

具体来说，训练样本从 `(file_text, next_token)` 变成了 `(diff + review_commentary, resulting_change_pattern)`。模型学到的不是"这段代码的下一个词是什么"，而是：

- 这条 review comment 暗示了哪种代码问题？
- 这个 diff 是修复 bug、添加功能、还是重构？
- 这个变更模式可能引入什么类别的回归？

这实际上是把代码审查的**意图层**编码进了模型的表示空间。

## 对三类工程任务的直接价值

### PR 摘要生成

现有模型生成的 PR 描述是在复述 diff，不是总结意图。"Added null check in user service" vs "Fix potential NPE when user session expires during payment processing"——后者需要意图推理，diff-level 预训练让模型天然区分这两种表述。

### 回归风险评估

当模型能看到 review 意图时，它可以推理：

```
review: "consider edge case where list is empty"
diff: removed .size() == 0 guard
→ 风险：高，意图暗示了原代码有防御性作用
```

这是当前"看 diff 猜风险"模型完全做不到的——它们没有意图上下文，只能做表面的变更大小估计。

### 重构影响面

diff-level 预训练模型可以学习"这类重构（提取公共方法）通常会波及其他调用点"，而不是把重构当成普通代码变更处理。

## 表示空间的转变

从表示学习的角度看，diff-level 预训练让模型的 code representation 多了一个"**变更意图轴**"。原来代码的 embedding 是静态的（这段代码做什么），加上这个轴之后，模型可以表达"这段代码经历了什么类型的变更"。

这意味着代码理解和代码变更理解现在共享同一个表示空间——做相似变更的代码片段在表示上会更接近。这个性质对代码搜索、变更聚类、遗留代码分类都有直接应用价值。

## 一个被低估的点：形式化验证的桥接

如果模型能理解"这条 review 暗示了什么约束"，它就可以把自然语言 review 转译为形式化规格（formal spec）。这比端到端生成代码更有工程可信度——因为约束是显式的、可验证的。

diff-level 预训练可能是通向"LLM 生成的形式化规格"的一条路径，而形式化规格是当前 AI 代码生成最缺的一环。

## 总结

从补全器到变更理由建模器，这个转变对软件工程工具链有结构性影响：

| 能力 | 文件级预训练 | Diff-Level 预训练 |
|------|------------|-----------------|
| 代码补全 | ✅ 强 | ✅ 持平 |
| PR 摘要 | 描述 diff | 推理意图 |
| 回归风险 | 变更大小估计 | 意图 + 变更模式 |
| 重构影响面 | 无 | 可学习 |
| 形式化规格桥接 | ❌ | ✅ 潜在可能 |

这不是一个微调 trick，而是预训练范式的转变——决定了这批代码模型能在软件工程链条里承担多深的任务。
