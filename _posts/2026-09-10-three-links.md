# 今日三条（2026-09-10）：把 Agent 当"受控系统"而非"聪明文本"

## 一、Failure-Grounded Test Synthesis：模型不会写测试，是因为没见过「失败现场」

大多数测试生成论文的核心逻辑是 Coverage（覆盖率驱动）或 Spec Alignment（规格对齐）。Failure-Grounded Test Synthesis 的思路则完全反直觉——**让 LLM 先看到系统怎么挂的，再反推该写什么测试。**

具体来说：以历史 bug、崩溃栈、CI 红状态作为「锚点」，用这些真实的失败现场来引导测试生成。实验结果很直接——相比规格驱动测试，失败锚定式测试多抓出了 **31% 的回归型缺陷**，且测试可读性更高，因为每个测试本质上在讲一个「故障故事」，而不是填充覆盖率指标。

这个方向对三个场景有直接启发：

- **Agent 写单测**：现有 Agent 写单测经常是"猜规格"，失败锚定让 Agent 有根可循
- **CI 自愈**：CI 红状态本身就是信号源，可以驱动针对性测试补网
- **Bug 回归库建设**：把每个 bug 的失败现场结构化，作为后续测试的种子

**核心洞察**：把「错误」当成一等公民，而不是训练后的残留物。错误不是"模型没学好"的副产物，而是系统知识的精华来源。

## 二、Context Lease & Revocation：Context 不是上下文，是租约

长任务 Agent 的经典困境："上下文只增不减，跑到一半开始漂移"。常见的解法是上下文压缩/摘要，但这只是「字数管理」，没有解决**权限与失效**的根本问题。

Context Lease & Revocation 提出了一个更硬的思路——把 OS 页表/内存回收的机制搬进 Prompt 管理：

- 每段记忆/文件片段有 **TTL（生存时间）、优先级与撤销条件**
- 当新意图进入时，**低租约上下文被回收**
- 回收动作本身写入审计流，可追溯

这和压缩摘要的本质区别在于：压缩摘要处理的是「信息密度」，租约模型处理的是**「权限与失效」**。一个是文本操作，一个是系统设计。

**核心洞察**：上下文不是仓库，而是流转的租约资源。当上下文管理从"堆"转向"租约"，Agent 才有可能真正 handle 长任务。

## 三、RC-Bench：Code Review 的瓶颈不是建议质量，是建议可信度

现有的 PR 评审 Agent 论文大多比的是"找不找得到问题"。RC-Bench 指出一个更隐蔽但更严重的问题——**「乱报」**：模型对错误建议给出过高置信度，人类 reviewer 反而被带偏，误修率反而上升。

RC-Bench 的贡献是提出了一个**校准基准**，衡量"建议置信度 ↔ 实际错误率"的校准误差。通过三种校准手段（温度调节、缩放校准、自反思），误修率下降了 **22%**。

**核心洞察**：Agent 进生产仓库后，"别瞎说"比"说得多"重要得多。评审场景会从「生成建议」走向「可问责建议」——不是给更多建议，而是让每个建议都可信赖。

- [SWRBench: 多评审聚合基准](https://arxiv.org/abs/2509.01494)

## 一句话串烧

> **测试从「规格」转向「失败」、上下文从「堆」转向「租约」、评审从「找错」转向「校准可信度」——前沿正在把 Agent 当"受控系统"而非"聪明文本"来设计。**

这背后的系统性思维很值得玩味：三个方向都在处理同一个底层问题——**Agent 的输出需要有边界、有失效机制、有可问责性**。不是让模型更聪明，而是让模型更可控。
