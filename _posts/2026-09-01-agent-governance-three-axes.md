## 一个共同的前提

过去一年，这个领域的默认叙事是：**让 agent 更强**。

更强上下文、更大窗口、更多采样、更长的 memory——这些方向的共同假设是：agent 能力不足是主要矛盾，补足能力问题就解决了。

但八月这几篇论文，它们的起点不是"agent 不够强"，而是"**更强的 agent 仍然需要控制**"。

写代码变便宜之后，真正的稀缺品回到了：谁来定义对、谁来决定够好、谁来签字负责。这三篇论文从三个不同方向回答了同一个问题——**控制面应该放在哪里**。

---

## 一、规格即控制面：MAGE 的外化思路

**MAGE**（Model-Based Agentic Software Engineering，arXiv:2608.25174）的核心洞察是：coding agent 让「写实现」变便宜后，稀缺资源回到抽象选择、验收证据与接受边界上。

它把项目意图、系统结构、验收义务外化为最小目的性表示：

- **constraints** — 约束条件，定义什么不能做
- **sensors** — 传感器，观测系统实际状态
- **validators** — 验证器，独立判断输出是否合规
- **gates** — 闸门，决定是否允许进入下一阶段

这套组合的本质是**可治理环境**：不是靠更长 prompt 或更大上下文补洞，而是让外部结构承担控制责任，同时保留"人权"——人类在边界处签字。

这对应一个重要转变：**架构文档不是给模型看的上下文，而是给自动化系统看的权威源。**

适合场景：agent 准入审核、合规审计骨架、跨团队接口契约。

**最大挑战**：谁来维护这套外化表示？这比写代码贵多了。

## 二、路由即裁判：Risa 的结构派 test-time scaling

**Risa**（Routing-Informed Steering and Arbitration，arXiv:2608.22960）没有在模型参数上做文章，它在**路由信号**上找答案。

核心观察：长轨迹 coding agent 重复采样时，原生 MoE router trace 本身携带行为角色信号——路由器在大量采样中积累的路由偏好，隐含了"哪个 patch 更可能对"的信息。

Risa 的用法：

- **轨迹内**：用路由偏好鼓励探索或受控收敛
- **轨迹间**：用「信息位路由一致度」选最终 patch

关键在于——**无需外部 judge，无需跑测试**，用模型自己的内部信号做仲裁。

这是 test-time scaling 的「结构派」打法：不是砸更多 token 做 uniform sampling，而是用结构信息指导采样聚焦。gpt-oss 宏均解决率 44.9%→48.2%，Qwen3.6 验证了可迁移性。

**值得注意的局限**：路由器当裁判的前提是它已经积累了足够的行为信号——成熟预训练模型上成立，从头训练的模型上这是废话。

## 三、对抗式少体协作：Adversarial Review 的结构化异议

多 agent 堆人头的方案边际收益递减，纯 subagent 又丢掉交互收益。**Adversarial Review**（arXiv:2608.18167）提出了一个最小结构：3 个角色。

- **coder**：写代码
- **reviewer**：审查代码
- **critic**：对 review 做结构化异议审计，再让 coder 改

关键设计不是让 agent 吵架，而是让 disagreement **最小化、有结构、绑定证据**。

LiveCodeBench 结果：超 5-agent 基线。SWE-PRBench 上揭示了一个重要的失败模式——**false-consensus**：无证据趋同，看起来大家一致，实际上是在拟合彼此。没有证据约束的多数投票，本质上是共识压缩而非智能汇聚。

加一句显式 disagreement 指令即拉回 F1。**这是可以直接抄进 PR review bot 和 agent 自检环的协议级方案。**

---

## 四、三条路的汇合点

| 维度 | MAGE | Risa | Adversarial Review |
|------|------|------|--------------------|
| 控制方向 | 向外：架构/治理 | 向内：模型信号 | 向交互：协议 |
| 核心机制 | 外化知识 + 独立评估 | 路由一致度仲裁 | 结构化异议 |
| 验证方式 | validators/gates | 信息位路由 | 证据绑定 F1 |
| 落地门槛 | 需要维护外化表示 | 依赖成熟 MoE 模型 | 3 个 prompt 即可实验 |

三条路各有限制，但它们有一个共同的前向路径：**如果这三个方向汇合——外化的架构约束 × 模型内部信号仲裁 × 受控异议协议——才是真正意义上的 agent 治理基础设施。**

现在各自都还在单点突破阶段。

---

## 写在最后

「更强的 agent」这个叙事还会继续。但八月这几篇论文提醒了一件事：

**当实现成本趋近于零的时候，决定系统行为的不再是能力，而是控制结构。**

这不是唱反调。能力是前提，但能力之上，需要有人决定做什么、不做什么、做到什么程度、谁来负责。这三篇论文各自戳了一个角，完整答案还在后面。
